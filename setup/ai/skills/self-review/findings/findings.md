# 指摘

個別 PR の再録ではなく、次の差分で同じ穴を踏んでいないかを確認するためのパターン。
「採用しなかった」とある項目は、同じ対象への再指摘をしない。

各項目の書き方:

- **適用条件**: この差分に当たるか
- **確認すること**: 当たったときに見ること
- **採用しなかったこと**: 任意。同じ対象への再指摘はしない

共通ファイルには、プロジェクト固有の名前、PR / チケットの URL や ID を書かない。コード例は汎用名にする。膨大になったら観点ごとにファイルを分割する。

## 呼び出し側に中間生成物を露出させず、目的の値を一発で返す

- **適用条件**: 差分で、最終的に欲しい値を得るために、呼び出し側で中間型・中間変数を経由する関数分割を新設・変更している（`tmp = methodA(input); want = methodB(tmp)` の形）
- **確認すること**:
  - 中間生成物が呼び出し側の目的ではなく、最終値を得るための一時変数になっていないか
  - 最終値を返す関数にまとめられるなら、呼び出し側は一発で最終値を得ているか
  - 手続き的で、各ステップが独立した副作用を持つ連続処理（テンプレート生成 → 送信など）なら許容する

例（NG）:

```
tmp, err := stepA(input)
result := stepB(ctx, tmp)
```

例（OK）:

```
result, err := stepB(ctx, input)
```
